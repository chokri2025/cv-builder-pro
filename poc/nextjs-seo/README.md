# CV Builder Pro — isolated Next.js SEO PoC

**Status: prototype only. NOT production-ready. NOT yet build-verified.**

Scope:
- Homepage `/` (English only);
- `/resume/teacher` (English);
- `/fr/resume/teacher` (French).

The PoC reuses the current React/Vite project's existing *pure* SEO content functions via sibling-file imports, without changing the main application. The current CV editor, localStorage, ATS checker and PDF/DOCX exporting stay on the production Vite app.

## Why separate root layouts?
English and French receive different `<html lang>` values. Routes are static Server Components. Metadata is generated with the Next.js Metadata API; **do not run the current client-side `useSEO` hook** in this PoC.

## Run (once dependency installation is possible)

Requirements: compatible Node.js for Next 16 and pnpm.

```bash
cd poc/nextjs-seo
pnpm install
pnpm typecheck
pnpm build
pnpm start
```

The nested `pnpm-workspace.yaml` isolates dependencies and lockfile from the production workspace. The `turbopack.root` setting enables importing the existing SEO content modules.

## Non-production precautions
- `robots.ts` disallows all crawling.
- Metadata carries `noindex, nofollow`.
- Canonical URLs point to the **existing** production domain for parity comparisons, not to the preview URL.
- No backend, database, OpenRouter key or real CV data.
- No domain change, redirects, or Vercel project settings changes.

## Required validation before any PR is merged
1. Install dependencies; commit the nested `pnpm-lock.yaml` generated by pnpm.
2. `pnpm typecheck` and `pnpm build` pass; ensure **all three HTML pages** are generated.
3. View source, not just DOM. Per page: exactly one canonical and one alternate per supported language; matching title/description/JSON-LD and correct `<html lang>`.
4. `/resume/customer-service-los-angeles` returns a proper 404 **inside the PoC** (legacy production policy remains undecided).
5. Verify `/sitemap.xml` and `/robots.txt` (preview is intentionally blocked).
6. No duplicate FAQ/Organization JSON-LD on the test pages.
7. Verify preview protection/noindex, Vercel build and Core Web Vitals.
8. Do **not** promote to production until a complete URL inventory has decisions for all indexed legacy URLs, plus an editor migration and feature parity test plan.

## Known deliberate gaps
- Only three proof-of-concept URLs; not a full site migration.
- Imported copy is currently reused as-is, including content-quality issues. This tests rendering/metadata, **not** content relevance.
- No CI/build execution has been run yet from this environment.
- Legacy 301/404 routing must be decided from Search Console evidence before the cutover.
